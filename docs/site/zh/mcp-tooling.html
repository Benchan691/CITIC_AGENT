MCP 与工具路由

命名解剖

全限定名 = mcp__<服务器>__<原始工具>。mcp__splunk_mcp__splunk_run_query 中 splunk 出现两次 — 一个产品词、两个层，仍是单一服务器。三层标识符：插件 id（splunk-official-mcp）→ 插件包（dsh-soc-agent/splunk-bridge）→ MCP 命名空间（splunk_mcp）。

不是工具的名字：ui__soc_agent__send_email（UI 确认目录条目 — 人工发送路径，模型不可调用）与 skill（无前缀宿主工具）。

名字 vs 行为陷阱。zimbra_send_email 不发信 — 只建本地草稿（只读分类，标签"Create email draft"）。zimbra_forward_email 同样只出草稿（读取原信、内嵌转发元数据）。检测技能引用的工具本轮已随 Splunk 栈删除。

路由层

  1. 注册：原始 allowedToolNames — soc_agent 精确 28、splunk_mcp 13 读 — 全部源自 tool-inventory.js。
  2. 限制：agent 工具集限制为 DOMAIN_TOOLS ∪ CONTROL_TOOLS。
  3. 执行：tools/pre-execute 精确名门；模式/状态；ask 进失败关闭的审批瀑布。
  4. 身份元数据：soc_session_id、soc_investigation_id、空 soc_customer_id、soc_correlation_id、soc_deadline_ms。
  5. 输出：Splunk 结果投影；其余信封整形。

两个服务器

soc_agentsplunk_mcp
是什么本地 Python FastMCP（stdio 子进程）到外部官方端点的客户端桥接
工具28：13 邮件、9 过滤器、6 订阅13 只读
身份登录用户（Postgres 会话 → 本人 Zimbra 令牌）环境中的服务令牌（Bearer）
失败拉起失败致命缺配置即禁用；其余按调用报错

漂移防护

三个同步清单现在合一（tool-inventory.js）；两端测试钉扎：test_server_tools.py（len==28）↔ skills.test.js；policy.test.js（30/42/12）；splunk-bridge.test.js（只读桥）。改工具走 开发页的六合同步清单。
