快速开始

核对基准：提交 56c8dd21492a5c36cb9f3eaa3da01160aba40033（2026-09-12T07:22:44Z）· 文档核对日期 2026-09-12。
对应英文页：../getting-started.html；Markdown 权威源：zh/GETTING_STARTED.md（如存在）。

前置要求

Node ^22.19.0 或 >=24；pnpm、uv、Git；Python 3.12（uv 管理）；可达的 PostgreSQL（APP_POSTGRES_URI，缺失则登录失败关闭）。外部服务：Zimbra 主机；官方 Splunk MCP 端点 + 令牌（必填）；可选订阅服务；运行时配置的 LLM 密钥。

五种安装形态

场景命令行为
全新安装bash setup.sh（bootstrap）提示仓库 URL/路径/分支；克隆后转入完整安装
已有 checkout./setup.sh交互：检查 → 参数 → env 文件 → Python 环境 → harness 构建 → 插件装配 → 摘要（不启动服务）
仅审计./setup.sh --check只报告；缺项 exit 1；从不写入
非交互修复./setup.sh --plugins（+--rebuild）重装/修复/重装配；无提示
更新./update.sh拒绝脏树；ff-only；随后 --plugins；手动重启

配置准备（安全）

setup 写入根 `.env` 与服务器 server/.env（均 chmod 600）；机密静默输入；密钥留空自动生成。纯净 vendor 不接收运行时环境文件。必填：SOC_ADMIN_EMAIL/PASSWORD（缺之宿主不启动）、APP_POSTGRES_URI + APP_SETTINGS_ENCRYPTION_KEY（登录）、ZIMBRA_HOST；官方 Splunk MCP SPLUNK_MCP_ENDPOINT + SPLUNK_TOKEN（setup/检查即要求）。绝不要把机密粘贴进 shell 命令。

启动与首次验证

pnpm dsh web --no-open        # 打开 http://127.0.0.1:3080

验证顺序：--check 通过 → Sentinel 登录遮罩 → 本人 Zimbra 登录 → 管理端 Connections 的 Splunk/订阅检查 → 分析师读工具自动执行、变更触发审批 → 建草稿观察 Send 门。

首启常见故障

症状首查
登录总失败APP_POSTGRES_URI 可达？Zimbra 直连可行？
无 Splunk 工具端点+令牌需齐备（setup 也要求）；日志 "official Splunk MCP bridge disabled"
Zimbra 工具失效Python 拉起失败（致命）；uv sync；加密密钥
界面陈旧被跟踪的 lib/ 未重建
