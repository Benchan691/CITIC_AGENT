运维、配置与数据

核对基准：提交 56c8dd21492a5c36cb9f3eaa3da01160aba40033（2026-09-12T07:22:44Z）· 文档核对日期 2026-09-12。
对应英文页：../operations.html；Markdown 权威源：zh/DEPLOYMENT_AND_OPERATIONS.md。

构建/测试/部署生命周期

setup doctor 阶段：布局守卫 → 前置（node/pnpm/uv）→ 参数收集（单一清单；官方 Splunk MCP 端点+令牌必填）→ env 文件（0600）→ uv sync → 指纹门控的 harness 安装/构建（SOC bundle 漂移自动修复）→ 插件添加/清理 → SOC bundle 注册 + 解析校验 → 摘要（掩码值；不启动服务）。--check 只读审计；--rebuild 强制重建。

更新：update.sh 拒绝参数与脏树，当前分支 ff-only，跑 setup.sh --plugins，提示手动重启。回滚是手动 git checkout 上一提交 + 重跑 setup；仓库内无数据库备份命令 — 与 APP_SETTINGS_ENCRYPTION_KEY 一起备份数据库。

健康：./setup.sh --check；管理 Connections 的 Splunk（实时 splunk_get_info）与订阅检查；启动日志（桥接禁用行、Python 拉起失败致命）。用 soc_correlation_id 关联日志。

配置优先级

必填键按条件：恒需 SOC_ADMIN_EMAIL/PASSWORD；登录需 APP_POSTGRES_URI + APP_SETTINGS_ENCRYPTION_KEY；按服务需 ZIMBRA_HOST、SPLUNK_MCP_ENDPOINT+SPLUNK_TOKEN（setup 即要求）、SUBSCRIPTION_SERVER_URL/USER/PASSWORD。机密绝不进 shell 历史/工单/文档。重启规则：env 变更 → 宿主重启；管理设置 → 实时；客户端变更 → 重建 bundle；补丁变更 → 重启（+ 装配时跑 setup）。

数据与持久化

PostgreSQL 是唯一重要的持久存储：soc_users、soc_app_sessions（Zimbra 令牌 Fernet 加密；Node 查询省略该列）、soc_session_revocations（一次性）、归属声明（工作区/会话/文件夹）、加密 app_config、遗留 zimbra_accounts、迁移台账 soc_schema_migrations。Schema 由版本化 SQL 迁移拥有（advisory 锁）。工作文件在 .data/soc-workspaces/<userId>/。保留：会话 24 h 惰性删除；对话保留未定义（未知）。并发：属主保护 upsert、revision 校验设置、过滤器指纹、有界线程池（8 全局/2 每主体）。

存储类别要点
PostgreSQL存储Node 池 max 10；Python 池 1–4、15 s 语句超时
按用户工作区敏感路径校验、符号链接安全包含
.env 文件敏感0600；从不提交；管理变量不进 Python 子进程
lib/ bundle生成被跟踪；setup 自动修复漂移
