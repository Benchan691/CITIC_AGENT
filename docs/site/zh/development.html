工具链与命令

安装/修复./setup.sh 或 ./setup.sh --plugins
宿主 JS 测试（35）cd apps/soc-agent && npm test
客户端测试（12）cd packages/soc-agent-client && npm test
Python 测试（39）cd apps/soc-agent/server && uv sync --extra test && uv run pytest
重建客户端 bundlepnpm --filter dsh-soc-agent-client run build
启动应用cd vendor/deepseek-harness && pnpm dsh web --no-open

无活跃 lint/钩子（lefthook.yml 全注释）— 手动对齐周边风格。全部套件离线运行；无 skip；仓库根无 CI。

依赖模型与生成边界

vendored harness 的工作区包含本仓库（workspace:* / link:）。根 requirements.txt 是外部 pnpm 插件清单（与 setup.sh 的 PLUGIN_NAMES 数量校验）；服务器 pyproject.toml/uv.lock 才是 Python 依赖。lib/ 是 被跟踪的生成产物 — 改后重建并一起提交。

改一个 MCP 工具 — 六合同步清单

  1. tool-inventory.js 加名（标签/kind）。
  2. Python 在对应 register_tools 模块实现（读工具标 readOnlyHint；无 ctx/account_id）。
  3. cordis.patch.yml 原始允许列表。
  4. policy.js 从清单派生 — 分类逻辑不变则无需改。
  5. 双端测试（test_server_tools.py 精确集；policy.test.js/skills.test.js 计数 30/42/12）。
  6. 文档（工具目录、路由页、可追溯矩阵）。
  7. 覆盖缺口

vendor 变更经 cordis.patch.yml 行、patches/*.patch、或预设保持可复现 — 绝不编辑 vendored 源码。Schema 变更走新的 migrations/NNN_*.sql（advisory 锁、台账）。

覆盖缺口

无端到端浏览器测试；转发链路分段测试；SQL 替身运行；setup.sh/update.sh 未测；仓库根无 CI。细节：测试覆盖矩阵（中文）。
