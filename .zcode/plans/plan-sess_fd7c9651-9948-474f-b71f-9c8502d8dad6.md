## Method (why it's safe)
Prod is touched **read-only** (REST GETs + bounded raw event exports). Test is written to via REST (create-only) and root SSH (`splunk add oneshot`). No bucket copying — impossible here and unnecessary since test (10.4.2) is newer than prod (10.0.9).

## Copy order

**0. Preflight & pilot (~15 min)**
- Snapshot test baseline: indexes, apps, `df -h` → saved to `~/splunk_import_manifest_2026-09-02.md` (the manifest records everything created/deleted; basis for rollback).

- **Throughput pilot**: export 1 hour of `g41228_palo_alto_firewall` to gz locally, measure MB/min → calibrates all time windows so total export ≈ 4–5GB gz.

**1. Create targets on test (REST, additive only)**
- Create missing indexes with same names as prod (`ticket_summary`, `g41228_*`, etc.) with bounded retention (`frozenTimePeriodInSecs=90d`, `maxTotalDataSizeMB≈8192`). `main`/`summary` already exist on test (empty) — reused as-is, nothing overwritten.

**2. Lookups / CSVs / supporting config (before data, ~30–60 min)**

**3. Event data (~4–5GB export; 2–6h depending on tunnel speed; resumable)**

- Per (index, sourcetype, time-slice ≤1h): `curl POST /services/search/jobs/export` `output_mode=raw` → `gzip` locally → scp → `splunk add oneshot <file>.gz -index X -sourcetype Y`. Sequential exports (one at a time, prod-friendly), slices ≤~500MB gz so a dropped tunnel resumes cleanly. _time comes from raw timestamps (present in pan/fortigate/wec data); sourcetype/index preserved per file; `_cd/_bkt/host/source` differ from prod — acceptable for test.

**4. Saved searches + dashboards (~1–2h, mostly API calls)**
- GET prod `/servicesNS/-/-/saved/searches` (app `search` ≈3,997 + `g41228_GTJA`), POST to test with `disabled=1` — **all alerts imported disabled, and email/webhook/script alert actions stripped**, so nothing fires from test.
- Dashboards (`data/ui/views`) + nav imported likewise. Existing titles on test are skipped (logged), never overwritten.

**5. Verify, cleanup, manifest (~30 min)**
- On test: per-index/sourcetype `tstats` counts vs prod same-window counts (tolerance ±5%); run 3–5 imported searches; spot-open 2–3 dashboards; check `_internal` for parse/license errors; confirm zero alerts scheduled-enabled; `df -h`.
- Delete staging `.gz` on both ends. Manifest finalised with every created object + skipped items → `~/splunk_import_manifest_2026-09-02.md`.

## Safety measures
- **Prod**: GETs and bounded sequential exports only; no writes, no config changes, no `outputcsv`; off-peak scheduling recommended.
- **Test**: strictly additive (new indexes, new objects, stub app); alerts disabled + alert actions stripped; credential-like lookups excluded; retention bounds protect the 30GB disk; existing apps (newer TAs, MLTK) untouched.
- **Credentials**: prod/test passwords used transiently in command args only — never written to scripts, repo files, or history.
- **Governance**: single tenant (g41228) + internal indexes only — no broad cross-tenant dump; copy approved by you today.
- **Rollback**: everything is additive — drop copied index data (REST delete index + rm index dirs), delete stub app and imported KOs (REST DELETE), per the manifest.
